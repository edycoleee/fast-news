# M11.1 — Internal Security Baseline Assessment

## Tujuan

Dokumen ini menilai baseline keamanan NewsHub untuk aplikasi internal yang:

- dapat diakses melalui internet;
- memiliki kurang dari 500 user;
- hanya digunakan user internal;
- tidak membuka registrasi publik;
- belum memerlukan platform compliance enterprise penuh.

Tujuannya adalah menentukan kontrol yang sudah ada, yang belum lengkap, dan prioritas implementasi coding berikutnya tanpa membuat arsitektur terlalu kompleks.

## Matrix status implementasi

| Baseline | Status | Bukti implementasi | Gap |
|---|---|---|---|
| HTTPS + cookie aman | TLS-ready | cookie `Secure`, Nginx security headers, request cap, dan template SSL tersedia | TLS/certificate/redirect hanya diaktifkan saat domain production tersedia |
| RBAC + session revocation | Sudah, baseline | list own/all, revoke selected/other sessions, audit, dan UI Settings tersedia | auto-revoke setelah password/user disable menunggu fitur tersebut |
| Argon2id, CSRF, validation, upload safety | Sudah | Argon2id, CSRF dependency, Pydantic, sanitizer, MIME/content/size validation | lanjutkan test regression dan secure development review |
| Rate limit + login cooldown | Sudah | PostgreSQL fixed-window bucket, login rate per IP, account failure/cooldown, comment/upload limits | observability dan alerting belum tersedia |
| Backup + uji restore | Implemented, scheduler pending | `pg_dump`, SHA-256, retention, restore guard, Docker ops job, dan runbook tersedia | scheduler, encrypted storage, dan restore drill dikonfirmasi saat deployment |
| Audit log + monitoring minimum | Sudah, baseline | readiness, structured JSON log, correlation ID, login/session events, audit filter dan CSV export tersedia | alerting eksternal masih P1 |
| Dependency/secret scanning | Sebagian | `npm audit` tersedia dan pernah dijalankan | belum ada `pip-audit`, Gitleaks, Bandit/Ruff, Trivy, SBOM, atau CI workflow |
| Retention + orphan cleanup | Sebagian | retention audit/session/rate limit runtime, batch cleanup, dry-run, cleanup audit, dan Docker log rotation tersedia | orphan file scheduler/archive policy masih P1 |

## Status ringkas

- **Sudah matang:** Argon2id/CSRF/validation/upload safety, rate limit/login cooldown, session management, dan audit/readiness monitoring.
- **TLS-ready:** template dan security headers tersedia; aktivasi menunggu certificate/domain.
- **Backup-ready:** script dan Docker ops job tersedia; scheduler/restore drill menjadi acceptance deployment.
- **Sebagian:** CI scanning dan retention/orphan cleanup.

## Prioritas implementasi

### P0 — sebelum production

1. **TLS dan production headers**
   - port 443;
   - redirect HTTP ke HTTPS;
   - TLS certificate;
   - HSTS;
   - CSP;
   - `X-Content-Type-Options`;
   - frame protection;
   - `Referrer-Policy`;
   - `Permissions-Policy`.

2. **Backup dan restore**
   - scheduled `pg_dump`;
   - encrypted backup;
   - retention 7/30 hari yang proporsional;
   - restore script;
   - restore drill dan bukti hasil;
   - backup metadata/file storage bila diperlukan.

3. **Session management**
   - list active session;
   - revoke selected session;
   - revoke all sessions;
   - revoke session saat user dinonaktifkan atau credential berubah;
   - audit perubahan session.

4. **Security visibility minimum**
   - audit login success/failure;
   - audit permission denied/CSRF/rate-limit;
   - structured logging;
   - request correlation ID;
   - admin audit view dengan filter dan export sederhana;
   - alert minimum untuk repeated failures dan dependency/container finding.

### P1 — setelah production stabil

5. **CI security checks**
   - `pip-audit`;
   - `npm audit`;
   - Bandit dan Ruff;
   - Gitleaks;
   - Trivy container scan;
   - SBOM generation;
   - failing threshold hanya untuk critical/high yang disepakati.

6. **Retention dan cleanup**
   - audit log retention policy;
   - scheduled orphan file cleanup;
   - cleanup report;
   - archive/delete rules yang dapat dijelaskan.

7. **Settings security history**
   - reason wajib pada perubahan setting sensitif;
   - version/history;
   - rollback setting;
   - compare active setting dengan baseline.

8. **Retention report**
   - jalankan cleanup dry-run;
   - jalankan batch cleanup terjadwal;
   - archive audit sebelum deletion bila policy mensyaratkan;
   - monitor eligible/deleted counts.

8. **Access review sederhana**
   - remove role dari user;
   - remove permission dari role;
   - review kuartalan;
   - export role/permission snapshot.

### P2 — hanya jika risiko meningkat

- MFA/SSO organisasi;
- SIEM terintegrasi;
- tamper-evident audit archive;
- custom malware analysis pipeline;
- multi-region/high availability;
- dedicated HSM;
- incident workflow kompleks.

## Acceptance criteria P0

### TLS

- HTTP redirect ke HTTPS;
- semua route production berjalan melalui HTTPS;
- Secure cookie aktif;
- HSTS hanya aktif setelah endpoint HTTPS stabil;
- security header diuji;
- certificate renewal/runbook terdokumentasi.

### Backup

- backup dapat dijalankan otomatis;
- hasil backup mempunyai lokasi dan retention;
- restore berhasil pada database test;
- restore tidak dijalankan terhadap production;
- hasil restore direkam sebagai evidence.

### Session

- user hanya dapat mengelola session miliknya;
- admin dengan permission khusus dapat revoke session lain;
- revoke one/all memakai CSRF;
- semua revoke menghasilkan audit log;
- session revoked tidak dapat kembali digunakan.

### Monitoring

- event security penting tersedia di log/audit;
- request mempunyai correlation ID;
- log tidak menyimpan password, token, atau secret;
- admin dapat memfilter event penting;
- alert/runbook minimum terdokumentasi.

## Keputusan scope agar tidak over-engineering

Untuk kurang dari 500 user internal, jangan langsung membangun:

- microservices;
- SIEM enterprise mahal;
- SOC 24/7;
- service mesh;
- multi-region;
- HSM;
- cryptographic log chain/blockchain;
- custom CAPTCHA tanpa indikasi abuse;
- certification platform penuh.

Kontrol dapat dimulai dengan script, scheduled job, export sederhana, dan runbook. Tambahkan tooling enterprise hanya bila scale, regulasi, insiden nyata, partner eksternal, atau audit formal mengharuskannya.

## Urutan kerja follow-up

```text
1. Aktivasi TLS saat domain/certificate tersedia
2. Scheduler backup + restore drill pertama
3. CI dependency/secret/container scanning
4. Retention + orphan cleanup
5. Access review + settings history
6. Alerting eksternal bila risk/scale membenarkan
```

## Residual risk saat ini

Residual risk yang masih terbuka:

- TLS/certificate belum aktif pada production;
- backup belum dijadwalkan dan restore drill belum pernah dijalankan;
- alerting eksternal belum aktif;
- audit log belum mempunyai retention management;
- retention archive/export automation belum dijalankan;
- scanning keamanan belum menjadi CI gate.

Residual risk ini perlu diterima sementara secara eksplisit atau dimasukkan dalam tindakan M12.
